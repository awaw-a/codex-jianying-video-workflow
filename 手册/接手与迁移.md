# 接手与迁移

接手从项目 `AGENTS.md` 指向的 `PROJECT_STATE.json` 开始。状态确定“当前看哪份工程、哪份导出、还缺什么”；它不是工程本身。具体字段以 [项目模板](../templates/project/PROJECT_STATE.json) 与主 skill 的 [项目契约](../skills/jianying-amv-workflow/references/project-contract.md) 为准。

## 新 agent 接手

> 使用 $jianying-amv-workflow 接手「项目目录」。先读 AGENTS.md 和唯一状态入口，再核对最新原生草稿、实际导出指纹、最近审核和用户未完成的反馈。不要运行历史生成脚本覆盖草稿。先告诉我已经完成、仍待验证和下一步；确认事实后继续当前任务。

agent 应依次核对：

1. 当前工作目录、个人 profile 版本、项目例外和自己的职责。协作者不能擅自接管 UI。
2. 权威原生工程的实际目录、保存／重开状态、完整备份与缓存。若状态路径失效，先定位，不从旧 EDL 擅自重建。
3. 最新导出的路径、指纹、画幅、实际帧数与停止点。核对它对应哪个原生版本。
4. 当前有效的素材边界与使用台账、审核覆盖和未验证事项。过期审核不得当作新版本证明。
5. 用户已经授权的下一步及反馈，特别是有没有实际听审。接手不是重新询问所有已确认偏好。

若事实矛盾，只暂停依赖这一事实的写入，继续只读核对。修改后由主 agent 更新状态，再生成接手页。不要让多份 README、临时说明和进度 JSON 各自宣布不同的“终版”。

真实案例中，打包时当前原生草稿的指纹与此前已重开的完整快照不同，而历史导出指纹保持不变。正确处理是保留两份原生身份，把当前草稿与旧导出的关系标为未验证；加密内容的字节变化不能直接证明画面变了，旧快照的重开证据也不能自动覆盖当前草稿。

## 迁移包需要带什么

| 内容 | 为什么必须保留 | 检查方式 |
| --- | --- | --- |
| 最新原生草稿完整目录 | 保存后可能加密；UI 改动不能由旧明文重建 | 保存、退出编辑器后快照；逐文件清单与指纹；重开验证 |
| 原生抠像／特效等缓存与必要关联数据 | 只带 draft_content 可能丢已处理结果 | 记录相对路径、文件数、大小与关联；重开及小导出确认 |
| 已用媒体与衍生素材 | 原路径换盘符后会失联 | 使用台账对实际依赖；复制后指纹核验，保留来源与时钟 |
| 字体文件和许可 | 新机可能回退字体或缺字 | 合法复制／安装；在剪映看实际字形与排版 |
| 全部原片索引 | 未用原片不必都复制，但后续扩镜需可定位 | 保存集数、音轨、时码、原路径与指纹类型；缺原片仍明确列出 |
| 状态、台账、设计与必要审核 | 新 agent 需要区分当前事实与历史 | 主入口可读；证据绑定版本；外部历史图片说明不可随意推定存在 |
| 工具、模板和运行要求 | 可继续检查而非依赖旧会话记忆 | 记录版本／依赖；新机检测运行环境，不硬编码旧机器路径 |

“已用媒体”与“保守依赖快照”要分开。缓存或旧 prepared 可能多记录未启用资产，宁可在清单标明保守包含，也不能无证据地称它们全部 active。首尾抽样指纹用于识别原片时必须注明不是全文件 SHA256；需要严格完整性时另做全哈希。

移机包不等于剪映安装包，也不携带新服务凭证。视频工具运行时可以在新机重新探测或安装，下载来源与版本单独记录；不要把某台机器的应用内 FFmpeg 路径当作必然存在。

## 原机器打包

先保存原生工程、确认处理完成，再退出编辑器，避免正在写入的缓存被不一致地复制。对当前完整草稿和必要关联目录制作新的快照；不要覆盖上一个可恢复备份。包内文件清单应含原位置、包内相对位置、角色、大小和指纹。

主 agent 核对状态与依赖台账后，用 `pack-project --state … --out …` 输出到新目录。先用 `--no-write` 查看将打包哪些依赖和缺项。路径解析、读取失败、许可不允许复制和无法确认归属的缓存都应进入报告，不能悄悄略过。

若保存的原生内容已加密，工具只能保留字节和整理依赖，不能承诺替换内部所有绝对路径。避免用旧明文覆盖它来“方便迁移”。需要在新机使用剪映提供的重链接／导入机制，并重新验证。

## 新机器恢复

1. 把包复制到新的工作目录，核对文件清单与指纹，保留一份未动原始快照。
2. 在该机用户目录运行 `安装与初始化.py install`，验证技能发现；安装字体时遵守许可。不要把旧用户名照抄进路径。
3. 探测实际剪映版本、草稿位置、运行时、媒体读取和编码器；记录与旧机不同的地方。
4. 从副本导入／定位原生草稿，重链接已用媒体。逐项检查缺素材、抠像缓存、字体和效果资源。资源 ID 在不同版本可失效。
5. 重开工程，检查时间线、总时长、层级、原生抠像和歌词；选择覆盖不同功能的短段做新机导出。
6. 做实际导出与旧交付的关键帧／声音对照。由于编码差异，不要求视频逐像素相同，但主体、文字、边界和音乐时钟必须正确。
7. 完整新机导出通过后，主 agent 将新路径与迁移证据写入状态；用户真实听审仍按项目状态执行。

完成复制、在同一电脑换文件夹演练、在另一台电脑重开并导出，是三个不同级别。报告必须说清测试是哪一级。当前实际结果以 [验收报告](../验收报告.md) 为准，不能从本流程说明推断已经跨机通过。

## 迁移验收条件

迁移“可继续编辑”至少需要：所有当前实际依赖可访问；原生草稿重开可编辑；抠像／字体／层级／蒙版确实显示；总时长与媒体时钟合理；新机短导出覆盖关键功能并通过实像检查；缺少的未用原片在索引中可定位。仅文件数一致不够。

迁移“交付已复验”还需要完整新导出、对应版本的独立检查、重要声音区间真实试听和用户听审结论。旧审核可以作为比较基线，不能替代新机结果。
