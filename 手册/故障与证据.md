# 故障与证据

本页处理能力发现、原生制作与验证的常见问题。遇到问题先保住最新已保存工程，再用副本或小样定位原因；不要用历史脚本重建主工程。

## 技能没有出现或规则不对

官方文档列出的个人技能目录是 `~/.agents/skills`；技能可被显式选择，也可按描述匹配。发现未刷新时可以重启后验证，同名技能不会合并。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)

官方 AGENTS 说明区分全局与项目指令；`AGENTS.override.md` 可能替代同层普通文件，非 Git 目录的发现范围也需留意。指令链在启动时建立，因此从目标目录验证实际来源。[官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

本包验收分三步：目标文件复制成功；新会话技能列表发现名称与路径；在实际提示中正确读取技能及对应 profile。不要把第一步写成第三步。若没有发现，检查 `SKILL.md` 文件名、元数据、同名冲突、禁用配置和实际用户目录；然后开新会话再试。无需为了本包擅自覆盖已有全局 AGENTS。

> 请只核对技能发现：列出 jianying-amv-workflow、video-media-review、video-workflow-learning 是否可用及实际路径。读取制作 skill 的入口和 profile，说明它们的范围；不要操作工程，也不要说已启用尚未发现的技能。

## 原生效果写了却看不见

| 现象 | 先检查什么 | 有效的验证动作 |
| --- | --- | --- |
| 蒙版注册了但画面全幅 | 本版本实际使用的材料类别、segment 启用开关、关键帧材料引用与时钟 | 独立新小样，用窄值到全幅值，在明确帧观察／导出 |
| 关键帧开头就展开或全段不动 | source_start、speed、局部目标时钟是否正确映射 | 对源非零入点＋非 1 倍速度做小样，再检查起／中／末帧 |
| 前景不能遮字幕 | 原生自由层级开关、各 segment 的轨道层级、文字是否被强制在视频上方 | 同位前景—文字—底图小样，实际观察字被挡住 |
| 展开后仍有黑边 | 中心偏移／旋转／全幅值是否真的覆盖画幅 | 展开后的安全端帧看四边，不只读 width=1 |
| 人物双影或错位 | source instant、缩放、位移、变速是否全一致 | 分别显示底图和前景，在同一帧对照位置 |
| 字体路径正确却不对 | 本机字体可读、原生字体字段、真实字形与缺字回退 | 打开原生界面与实际导出；亮底／斜体／标点也看 |

小样验证记录应用版本、输入指纹、参数组合、观察帧与结果。若只证明一个组合能用，就写这个组合；不要推断每个字段都独立必需，也不要把第三方开源结构当成本机原生实测。

## 抠像、UI 和处理状态

缓存文件存在不等于人物轮廓正确；首尾完整也不等于中间的双臂、细刀或腿间隙完整。原生处理后查看整个使用范围，特别是出框暴露边缘和两人物重叠的阶段。必要时在原生界面补选并 Apply，重新导出核查。

工具或用户切换过面板、素材、窗口或版本后，先重新读取当前可见状态，再操作。不要连续执行基于旧截图的坐标。预览没有变化时，分别确认选中对象、播放头、当前工程、处理是否完成和预览是否刷新；不要直接认定数据损坏。

安全／账号／网络弹窗需要用户处理时，把具体阻挡动作说明清楚。此时可以继续不依赖它的只读研究或审查，不发送基于假设窗口状态的后续点击。

## 原生草稿已经加密

《越过高塔》中保存后的 draft_content 是加密内容；可读 draft_info 仍是早期初始化状态。见案例 [明文读取核验](../examples/越过高塔/evidence/V4原生保存文件_明文读取能力只读.json)。可读性不能证明文件新旧，更不能证明它包含所有 UI 改动。

此类情况下先保存并退出编辑器，备份完整草稿及关联缓存、必要注册信息和文件清单；在副本重开验证。修改通过剪映原生 UI 完成。不要用旧 prepared JSON 覆盖最新草稿，也不尝试绕过加密、hook 或把未知字段猜进去。

快照需要记录创建时间、原生工程身份、文件数／字节、指纹和重开结果。一个 draft_content 文件的备份无法证明抠像缓存可恢复。备份过程错误或目标已存在时，换新的明确目录，不覆盖可恢复版本。

## 审核结论应该怎么写

| 能力或结果 | 可以说 | 不能仅据此说 |
| --- | --- | --- |
| 代码／JSON 检查 | 参数存在、引用和时钟算式一致 | 剪映实际生效 |
| 媒体解码 | 实际帧率、PTS、帧数、音频样本有限 | 镜头不串景、观感好 |
| 联系图／逐帧实看 | 实际看过哪些帧、可见错位／文字／边缘情况 | 全片所有帧通过、声音好听 |
| 原生 UI／小样 | 本版本这一组合实际可见 | 跨版本／跨机必然通用 |
| 波形、ASS、ASR | 音节边界辅助、能量／削波、低置信词 | 完整尾音听起来自然、歌词绝对准确 |
| 用户真实试听 | 指定导出与区间的听审结论 | 另一导出也自动通过 |

报告注明只读或写入行为、输入版本／指纹、检查范围、实际动作、问题与限制。数值检查、视觉检查和耳听三个结论单独写。创作建议也单独标明：暗室铺垫太慢是审美判断，末帧串到另一场景是可确认缺陷。

## 改完之后哪些检查失效

换镜／改源区间：重查边界、唯一性、同位前景和接点。改变速：重查时钟、音画、动作接触和效果关键帧。改字幕：重查各分层段、亮底、脸与打击避让。换原声：重查样本、完整句／尾音、变速与混音，并试听。改停止点：重查最后实际帧、所有轨道停止、音频编码尾与真实听感。

任何新导出都绑定新指纹；旧报告只能作为比较基线。使用 toolkit 的 `invalidate-evidence` 生成新的失效说明，由主 agent 决定重查范围并更新状态，不让审核者直接改主工程。
